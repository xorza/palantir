# Aperture simplification review

## Summary

Reviewed the production code under `aperture/src` and `aperture/anim-derive/src`, excluding tests, benches, showcase code, examples, and fixtures. The largest sources of avoidable complexity are record-pass replay, paint-kind reordering in the renderer, and retained state that is mirrored across layout, cascade, damage, input, and widget layers. The review found 14 high-priority, 11 medium-priority, and 4 lower-priority problems.

## High priority

- [ ] **Record replay has spread a second lifecycle protocol through the framework.** `App::record` may replay for warmup, action settling, or explicit relayout (`aperture/src/app.rs:15`), and the first frame can execute a hidden warmup, the visible pass, and a settling pass in one frame (`aperture/src/ui/mod.rs:203`). This requires input swapping and queue draining (`aperture/src/ui/mod.rs:229`, `aperture/src/input/mod.rs:761`), replay-idempotent window commands (`aperture/src/ui/mod.rs:609`), a dedicated discarded-ID set and rollover path (`aperture/src/scene/seen_ids.rs:122`, `aperture/src/scene/seen_ids.rs:239`), delayed cache sweeping (`aperture/src/ui/mod.rs:416`), an animation frame guard (`aperture/src/animation/mod.rs:268`), and a separate O(N) cascade ID snapshot because the live map is cleared between passes (`aperture/src/scene/cascade/mod.rs:317`). Application code must partition side effects between `update` and replayable `record`, while common input frames repeat the full record/layout/cascade pipeline.

- [ ] **Fixed per-kind backend replay creates a large compensating ordering subsystem.** A group always replays quads, text, meshes, images, then curves, so the composer must detect every overlap that would reverse authoring order and split groups around it (`aperture/src/renderer/frontend/composer/mod.rs:45`). That rule owns per-tier rectangle stores (`aperture/src/renderer/frontend/composer/higher_kind.rs:6`), a spatial text index (`aperture/src/renderer/frontend/composer/text_grid.rs:27`), batch anchors (`aperture/src/renderer/render_buffer/batch.rs:14`), and a second cursor-based ordering walk in the backend (`aperture/src/renderer/backend/schedule.rs:185`). The code documents that the original text scan dominated compose time, TinyVec dispatch alone cost about 2% of a frame, and clearing the replacement grid once consumed about 37% of composer self-time (`aperture/src/renderer/frontend/composer/text_grid.rs:1`, `aperture/src/renderer/frontend/composer/text_grid.rs:36`, `aperture/src/renderer/frontend/composer/text_grid.rs:63`). A batching choice therefore drives substantial code, hot-path work, and paint-order correctness machinery.

- [ ] **The measure cache is a manually synchronized shadow layout representation.** Live state is split among `LayoutScratch`, `Layout`, grid pools, text buffers, `CachedSubtree`, `CaptureTreeInput`, and `NodeArenas` (`aperture/src/layout/cache/mod.rs:38`, `aperture/src/layout/cache/mod.rs:51`, `aperture/src/layout/cache/mod.rs:89`). Capture manually serializes each column (`aperture/src/layout/cache/mod.rs:195`), and cache hits manually restore scroll, text, intrinsic, availability, and grid state (`aperture/src/layout/engine.rs:133`). The engine explicitly states that every new measure-to-arrange field requires three coordinated edits and that an omission silently corrupts arrange (`aperture/src/layout/engine.rs:47`). Layout evolution is consequently coupled to a second schema and bespoke serialization/restore paths.

- [ ] **Scene invalidation is fragmented across overlapping reuse gates and retained snapshots.** `Ui` first compares an outer cascade fingerprint (`aperture/src/ui/mod.rs:394`), then `CascadesEngine::can_update` independently validates display scale, counts, static hashes, arranged rectangles, and subtree ends (`aperture/src/scene/cascade/mod.rs:487`). The fingerprint separately enumerates cascade dependencies and warns that an omitted input silently reuses stale output (`aperture/src/scene/cascade/mod.rs:574`). After those gates, `DamageEngine` retains another widget map and paint arena containing hashes, cascade inputs, parent identities, and copied paint rows (`aperture/src/scene/damage/mod.rs:85`, `aperture/src/scene/damage/snapshot.rs:31`, `aperture/src/scene/damage/snapshot.rs:82`) alongside the retained cascade columns and paint arena (`aperture/src/scene/cascade/mod.rs:206`). Correct incremental rendering depends on several independently maintained representations agreeing about the same tree and paint state.

- [ ] **`DragValue` drops normal widget configuration when it enters edit mode.** The chip resolves the caller-configured `Node` (`aperture/src/widgets/drag_value/mod.rs:262`), but the focused branch replaces it with a fresh `TextEdit` that carries only ID, alignment, size bounds, selection behavior, and theme (`aperture/src/widgets/drag_value/mod.rs:396`, `aperture/src/widgets/drag_value/mod.rs:423`). Padding, margin, parent alignment, grid placement, canvas position, clipping, visibility, and other `Configure` fields from the public builder (`aperture/src/widgets/drag_value/mod.rs:455`) disappear during editing. Focus alone can therefore move, resize, re-layer, or re-clip the same widget.

- [ ] **Modal keyboard ownership disagrees with visual and pointer layer ownership.** Modal content paints above popups (`aperture/src/scene/layer.rs:8`) and consumes pointer input through its backdrop, but it tests Escape through the uncaptured stream (`aperture/src/widgets/modal.rs:69`, `aperture/src/widgets/modal.rs:99`). A popup registers exclusive keyboard capture (`aperture/src/widgets/popup/mod.rs:191`), and uncaptured reads become empty while any capture owner exists (`aperture/src/input/mod.rs:428`, `aperture/src/ui/mod.rs:485`). A visually topmost modal can therefore fail to receive Escape while a lower popup or focused main-layer widget owns keyboard events.

- [ ] **`Scroll` silently discards future `Node` fields despite documenting a compile-time drift guard.** Its wrapper split claims an exhaustive destructure will force every new field to be assigned to the outer or inner node (`aperture/src/widgets/scroll/mod.rs:360`), but the destructure ends in `..` (`aperture/src/widgets/scroll/mod.rs:373`). The function already manually routes sizing, placement, flags, visibility, padding, gaps, justification, and child alignment (`aperture/src/widgets/scroll/mod.rs:393`). A new `Node` field compiles without entering either wrapper, creating Scroll-only configuration loss.

- [ ] **Valid UI content can exhaust the gradient atlas and panic.** The atlas has only 255 usable rows (`aperture/src/renderer/gradient_atlas/mod.rs:51`). Registration protects every gradient referenced by the current frame from eviction (`aperture/src/renderer/gradient_atlas/mod.rs:194`), and `lru_victim` panics when all rows were touched in the epoch (`aperture/src/renderer/gradient_atlas/mod.rs:265`). A frame containing more than 255 distinct stop/interpolation combinations crashes a release application even though every individual gradient is valid.

- [ ] **`HostHandle::run_on_main` can silently lose arbitrary application-state work.** Repaint and quit events deliberately discard `send_event` errors, and `run_on_main` applies the same policy to an owned one-shot closure (`aperture/src/host/winit/handle.rs:76`). Its public signature returns no delivery status (`aperture/src/host/winit/handle.rs:84`), so an event-loop shutdown race destroys the closure and its mutation without observation or retry.

- [ ] **Occluded windows bypass the documented close-veto lifecycle.** A native close request deliberately schedules a frame so application code can observe `Ui::close_requested` and call `Ui::keep_open` (`aperture/src/host/winit/mod.rs:696`, `aperture/src/host/winit/mod.rs:707`). `Window::frame` copies the request into `Ui`, resets `close_vetoed`, and then returns before `App::update` or `App::record` whenever the window is occluded (`aperture/src/host/winit/window.rs:100`, `aperture/src/host/winit/window.rs:108`). The common output path sees the untouched veto flag and immediately enqueues the close (`aperture/src/host/winit/window.rs:185`, `aperture/src/host/winit/window.rs:190`). A minimized or otherwise occluded dirty-document window can therefore close without running its save prompt or any other application veto logic.

- [ ] **Popup keyboard ownership is corrected only after popup bodies have already consumed the frame's events.** Captured reads return events only to the retained `keyboard_capture` owner (`aperture/src/input/mod.rs:428`), while `capture_keyboard` merely appends the current popup and changes the live owner only when no prior owner exists (`aperture/src/input/mod.rs:443`). The visually topmost, last-recorded candidate becomes authoritative only in `finish_record` (`aperture/src/input/mod.rs:460`). `Popup::show` checks Escape inside its body before that finalization (`aperture/src/widgets/popup/mod.rs:194`, `aperture/src/widgets/popup/mod.rs:220`, `aperture/src/widgets/popup/mod.rs:231`), and context-menu shortcuts use the same in-body capture handle (`aperture/src/widgets/context_menu/mod.rs:305`, `aperture/src/widgets/context_menu/mod.rs:314`). When a top popup appears, disappears, or changes order, that transition frame's key can reach the previous popup or no popup instead of the one currently on top.

- [ ] **Closing a window can permanently strand its `GpuView` render targets in the shared backend.** Every `WindowDriver` owns a stable renderer identity (`aperture/src/host/window_driver.rs:39`, `aperture/src/host/window_driver.rs:46`), and target eviction deliberately retains every entry owned by a different identity (`aperture/src/renderer/backend/image_pipeline/render_target.rs:81`, `aperture/src/renderer/backend/image_pipeline/render_target.rs:86`, `aperture/src/renderer/backend/image_pipeline/render_target.rs:172`). Window closure removes and drops the driver without notifying the backend of that identity's retirement (`aperture/src/host/winit/mod.rs:489`, `aperture/src/host/winit/mod.rs:497`). The closed owner never submits again, while all surviving windows preserve its targets as foreign entries, so repeatedly opening and closing windows containing `GpuView`s leaks their GPU textures and bind groups until the entire host shuts down.

- [ ] **Dynamic `ComboBox` options have positional identity, so a stale click can activate a different current option.** Every option constructs `MenuItem::new` from the same loop call site and immediately applies its response to `options[i]` (`aperture/src/widgets/combo_box/mod.rs:128`, `aperture/src/widgets/combo_box/mod.rs:133`). Auto IDs repeated under one parent are disambiguated by occurrence order (`aperture/src/scene/node/mod.rs:47`, `aperture/src/scene/node/mod.rs:60`), while widget interaction is routed from the previous frame's cascade (`aperture/src/ui/mod.rs:911`, `aperture/src/ui/mod.rs:923`). Inserting, removing, filtering, or reordering options between event routing and the next record pass can therefore make a click on yesterday's row select today's different value; the public options API carries no logical key that could distinguish them.

- [ ] **`OffscreenHost::frame_offscreen` advances application and retained UI state before discovering an invalid target texture.** The public method accepts an arbitrary `wgpu::Texture`, but its only declared validation failure is an invalid scale factor (`aperture/src/host/offscreen.rs:184`, `aperture/src/host/offscreen.rs:201`). After validating only that scalar, it derives the target size and format and runs the full CPU application frame before handing the texture to the renderer (`aperture/src/host/offscreen.rs:229`, `aperture/src/host/offscreen.rs:244`). The target-size invariant is release-elided (`aperture/src/host/window_driver.rs:305`, `aperture/src/host/window_driver.rs:324`), and no boundary checks the texture's usage, dimension, sample count, or renderable/copy-compatible format before the backend creates a render view or uses it as a copy destination (`aperture/src/renderer/backend/mod.rs:574`, `aperture/src/renderer/backend/mod.rs:610`, `aperture/src/renderer/backend/mod.rs:1028`, `aperture/src/renderer/backend/mod.rs:1050`). Invalid external input consequently surfaces as a late GPU validation failure after application mutations, animation time, caches, and frame identity have already advanced.

## Medium priority

- [ ] **Grid track state exists in transient, durable, and cached forms.** `AxisScratch` owns sizes, resolution flags, and offsets while `GridHugStore` separately owns min/max pools, persisted sizes, totals, and slots (`aperture/src/layout/grid/mod.rs:51`, `aperture/src/layout/grid/mod.rs:141`). Measure copies resolved sizes into the store (`aperture/src/layout/grid/mod.rs:456`), arrange copies them back or re-solves through a zero-total sentinel (`aperture/src/layout/grid/mod.rs:636`, `aperture/src/layout/grid/mod.rs:754`), and the measure cache separately packs and restores hug arrays (`aperture/src/layout/grid/mod.rs:281`). The store is zero-built at layout start and then each measured grid zeroes its hug slices again (`aperture/src/layout/grid/mod.rs:181`, `aperture/src/layout/grid/mod.rs:383`), with the latter still documented around a grow-driven remeasure the engine says no longer exists (`aperture/src/layout/engine.rs:201`).

- [ ] **Scroll’s sparse output is represented as dense per-node state throughout layout caching.** Every layer allocates and zeroes one `Size` in `scroll_content` for every node (`aperture/src/layout/mod.rs:31`, `aperture/src/layout/mod.rs:77`), although only the scroll driver writes it (`aperture/src/layout/scroll/mod.rs:17`). The measure snapshot duplicates the full column (`aperture/src/layout/cache/mod.rs:39`, `aperture/src/layout/cache/mod.rs:89`, `aperture/src/layout/cache/mod.rs:195`), and every cache hit copies the entire subtree slice (`aperture/src/layout/engine.rs:148`). Non-scroll nodes pay live storage, snapshot storage, zeroing, and restoration costs for a scroll-only datum.

- [ ] **Input routing and frame scheduling are one distributed state machine.** `InputState` owns capture, focus, routed queues, subscriptions, the frame clock, action flags, and sticky repaint-classification bits (`aperture/src/input/mod.rs:255`). The event dispatcher mutates gesture state, queues, action classification, and repaint classification together (`aperture/src/input/mod.rs:525`). `Ui` copies those flags into a separate classification input (`aperture/src/ui/mod.rs:185`), and `FrameRuntime` combines them with wake reasons and output validity to choose a plan (`aperture/src/ui/frame.rs:180`). The scheduling meaning of one event is spread across three owners and several correlated flags.

- [ ] **Disabled response semantics are rewritten at three boundaries.** `InputState::response_for` starts from the previous cascade’s effective disabled state (`aperture/src/input/mod.rs:881`); `Ui::response_for` merges the current ancestor state and reconstructs the response to clear interactions (`aperture/src/ui/mod.rs:922`); interactive widgets then merge the current self-disabled flag for internal logic but preserve the earlier raw value for their returned response (`aperture/src/widgets/mod.rs:117`). Internal widget behavior and caller-visible state can disagree, and correctness depends on the projection order across input, UI, and widget layers.

- [ ] **The packed command buffer is a transient duplicate renderer schema.** `Frontend::build` immediately sends encoder output to the composer in the same call (`aperture/src/renderer/frontend/mod.rs:88`), yet every paint operation has a `CmdKind`, Pod payload, recording method, decoded `Command` variant, and composer match arm (`aperture/src/renderer/frontend/cmd_buffer/payload.rs:126`, `aperture/src/renderer/frontend/cmd_buffer/mod.rs:65`, `aperture/src/renderer/frontend/cmd_buffer/mod.rs:403`, `aperture/src/renderer/frontend/composer/mod.rs:433`). Non-Pod GpuView callbacks require a parallel side channel (`aperture/src/renderer/frontend/cmd_buffer/mod.rs:67`). The packed layout has a memory rationale (`aperture/src/renderer/frontend/cmd_buffer/mod.rs:10`), but every new primitive still spans two intermediate vocabularies and their conversion code before reaching `RenderBuffer`.

- [ ] **The top-level directories do not form dependency layers.** Scene’s `Node` owns layout vocabulary (`aperture/src/scene/node/mod.rs:5`) while layout imports scene trees and node columns (`aperture/src/layout/engine.rs:25`); `Shape` exposes a renderer-owned image handle (`aperture/src/shape/mod.rs:20`) while the renderer consumes scene records (`aperture/src/renderer/frontend/mod.rs:35`); `Ui` owns widget theme and returns `Widget` (`aperture/src/ui/mod.rs:49`) while the widget primitive imports and calls `Ui` (`aperture/src/widgets/mod.rs:26`). These cycles make directory ownership unreliable and cause changes to cross nominal layer boundaries in both directions.

- [ ] **Text-edit orchestration fragments one state transition across many transfer structs and repeated map lookups.** A frame moves substantially the same geometry and layout facts through `LayoutInput`, `ResolvedLayout`, `GeometryInput`, `FinalGeometry`, `ViewUpdateInput`, `ViewUpdate`, and `PaintInput` (`aperture/src/widgets/text_edit/input.rs:57`, `aperture/src/widgets/text_edit/view.rs:105`, `aperture/src/widgets/text_edit/view.rs:279`). `TextEdit::show` repeatedly reacquires the same `TextEditState` row for input, offsets, caret/selection, retained rectangles, text hashing, view update, and rectangle restoration (`aperture/src/widgets/text_edit/mod.rs:227`). The module split adds field plumbing and keyed-map work without assigning a coherent state transition to any one layer.

- [ ] **Overlay ownership is duplicated across leaky widget abstractions.** `ContextMenu` exposes a hand-picked node surface, builds its own themed body, then overwrites `Popup`’s private node representation (`aperture/src/widgets/context_menu/mod.rs:83`, `aperture/src/widgets/context_menu/mod.rs:143`, `aperture/src/widgets/popup/mod.rs:118`). `Popup` separately owns positioning, chrome, an input eater, layer selection, keyboard capture, and dismissal (`aperture/src/widgets/popup/mod.rs:178`), while Tooltip and Modal rebuild overlapping node/chrome/layer policy (`aperture/src/widgets/tooltip/mod.rs:178`, `aperture/src/widgets/modal.rs:69`). Common overlay behavior is therefore spread across several types that depend on each other’s representation.

- [ ] **`FillKind` combines unrelated contracts across authoring, composition, optimization, and shader code.** The type lives in `primitives` to work around dependency direction (`aperture/src/primitives/fill_wire.rs:1`) but contains brush tags, gradient spread, two shadow kinds, triangle geometry, and composer-owned optimization flags (`aperture/src/primitives/fill_wire.rs:32`). Triangle points reuse the corner and gradient-axis lanes (`aperture/src/renderer/frontend/composer/mod.rs:686`), composer optimizations depend on exact `FillKind::SOLID` equality (`aperture/src/renderer/frontend/composer/mod.rs:560`, `aperture/src/renderer/frontend/composer/mod.rs:598`), and WGSL manually decodes the same packed word (`aperture/src/renderer/backend/quad.wgsl:36`, `aperture/src/renderer/backend/quad.wgsl:333`). Unrelated paint, geometry, batching, and GPU changes are coupled through one wire value.

- [ ] **No-op correctness is described as canonical but remains split across shape and renderer layers.** The command buffer calls itself the single correctness gate and immediately documents polyline as an upstream exception (`aperture/src/renderer/frontend/cmd_buffer/mod.rs:25`). Lowered gradients cannot determine transparency and depend on the brush gate (`aperture/src/renderer/frontend/cmd_buffer/payload.rs:79`), polyline payloads depend on an authoring scan (`aperture/src/renderer/frontend/cmd_buffer/payload.rs:330`, `aperture/src/shape/polyline.rs:27`), and mesh duplicates its predicate at authoring and payload levels (`aperture/src/primitives/mesh.rs:102`, `aperture/src/renderer/frontend/cmd_buffer/payload.rs:369`). Visibility-policy changes require synchronized edits across multiple alleged sources of truth.

- [ ] **`Mesh::with_known_bbox` is an unused public escape hatch that permits silent rendering corruption.** The method accepts an unchecked AABB and explicitly states that an incorrect value breaks scissor culling (`aperture/src/primitives/mesh.rs:187`). The encoder forwards the value (`aperture/src/renderer/frontend/encoder/mod.rs:397`), and the composer uses it for both culling and cross-kind ordering conflicts (`aperture/src/renderer/frontend/composer/mod.rs:707`). No production caller uses the method; its only caller is its own test, while its presence expands the public contract with a path that can make geometry disappear or replay in the wrong order.

## Lower priority

- [ ] **Layout driver identity is repeated in three exhaustive dispatch trees.** Measure maps every `LayoutMode` to a driver (`aperture/src/layout/engine.rs:687`), arrange repeats the mapping (`aperture/src/layout/engine.rs:784`), and intrinsic sizing repeats it again (`aperture/src/layout/intrinsic/mod.rs:196`). The documented driver contract requires all three to change together (`aperture/src/layout/engine.rs:694`), and Scroll further delegates into stack/z-stack while keeping its intrinsic mapping elsewhere (`aperture/src/layout/scroll/mod.rs:17`, `aperture/src/layout/intrinsic/mod.rs:225`).

- [ ] **`URect16` is dead production code with stale documentation.** The type, hashing, conversions, and saturating constructor occupy `aperture/src/primitives/urect/mod.rs:102`, whose documentation claims it is used by `TextRun.bounds`. `TextRun.bounds` stores full-width `URect` (`aperture/src/renderer/render_buffer/text.rs:21`), and `URect16` has no production use outside its own definition and conversions.

- [ ] **The production text core carries a second shaper mode used only by gated support code.** Normal construction always installs cosmic shaping, yet `ShaperInner` stores it as an `Option` and production dispatch retains fallback branches (`aperture/src/text/mod.rs:109`, `aperture/src/text/mod.rs:217`, `aperture/src/text/mod.rs:262`). The mono implementation is compiled into the main crate (`aperture/src/text/mono.rs:1`), while the only constructor for the `None` mode is gated behind test/internals support (`aperture/src/text/mod.rs:406`). This widens production invariants and preserves a parallel measurement path for a non-production mode.

- [ ] **The derive macro supports two attribute names for one behavior despite the project’s no-compatibility posture.** `snap` and the documented `skip` alias enter the same parser branch and generate identical semantics (`aperture/anim-derive/src/lib.rs:16`, `aperture/anim-derive/src/lib.rs:173`). The duplicate spelling expands public syntax, documentation, parsing, and diagnostics without representing another capability.
