# Open issues

- `Staging::abort` (`src/gpu/surface/staging.rs`) unmaps a buffer whose `MapState` reads pending. wgpu-core 30's `Buffer::map`, run by a device poll, sets the buffer's map state to idle for the length of the map, so an abort on one thread while another thread polls the same device can unmap a buffer wgpu holds as idle: a "Buffer is not mapped" validation error, which `device_health` turns into a panic. The Windows CI runner hit it in `gpu::surface::map_state` tests on the shared test device. Waits on the wgpu release that carries https://github.com/gfx-rs/wgpu/pull/9959 (merged after 30.0.1, not on the `v30` branch).
- The `palantir` lib test binary sometimes dies with SIGSEGV in CI's `gate (ubuntu-26.04)` lane under `cargo gate-test` (`signal: 11`), with no failed test named: runs 42374343717 (`42a503d06`), 42280893167 (`bda517fb7`), 41913776381 (`a67ecb397`), 41486974536 (`63fc8c5e5`). The lane passes on later commits that hold `42a503d06`.
- `FontScope::System` documents installed fonts as glyph fallback, but `FontSystem::new_with_fonts` (`src/text/font_scope.rs`) loads them before the bundled faces, so an installed "Inter" or "JetBrains Mono" can replace the bundled face of that name, in the window and not in a `FontScope::Bundled` harness.
- `RequestedGpu` keeps wgpu's backend order among adapters of one rank (`src/gpu/device/requested_gpu.rs`), so a Windows machine with a Vulkan driver runs Vulkan, while the CI Windows lane runs Dx12 on WARP alone. Neither Windows with Vulkan nor Dx12 on a real GPU runs in CI.
- `.github/workflows/ci.yml` says Vulkan is the only backend this crate builds on Linux, but `Cargo.toml` enables `gles`.
- `oklab::cbrt` refuses the system's libm because its last bit differs by platform, but `animation/spring.rs`, `shape/paint/blur_plan`, `shape/paint/lens_optics`, the gradient geometry and `color/okhsv` still call it.
- `winit` 0.30 reports a Windows wheel in notches and does not read the system's lines-per-notch setting, and nothing in `src` reads it, so that setting has no effect on `ScrollLines`.
