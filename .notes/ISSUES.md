# Open issues
- `Staging::abort` (`src/gpu/surface/staging.rs`) unmaps a buffer whose `MapState` reads pending. wgpu-core 30's `Buffer::map`, run by a device poll, sets the buffer's map state to idle for the length of the map, so an abort on one thread while another thread polls the same device can unmap a buffer wgpu holds as idle: a "Buffer is not mapped" validation error, which `device_health` turns into a panic. The Windows CI runner hit it in `gpu::surface::map_state` tests on the shared test device. Waits on the wgpu release that carries https://github.com/gfx-rs/wgpu/pull/9959 (merged after 30.0.1, not on the `v30` branch).
- `BackdropFilter::min_luminance_for` returns `Result` but `after_storing` panics on `checked_add(1)` for an ink whose contrast ground stores as byte 255, so `Theme::from_parts` panics for a light popup with a mid-grey `text_muted` under `float_material`.
- Lerp and spring overshoot of `Corners`, `Stroke` width and `Shadow` blur can go below zero, which `Chrome` validation refuses with a release panic.
- `Stop::new` validates with `domain::color`, which admits HDR and negative channels, then stores `to_srgba8()`, which clamps them.
- `lower::chrome` sanitizes a NaN `Chrome` in release instead of refusing it at the public `Widget::record`.
- `Idx16` row tables (`bounds_table`, `panel_table`, `chrome_table`) panic in release past 65,535 rows a plane, which a non-virtualized grid of about 300×250 cells reaches.
- `FamilyKeys` mints a key per `FontFamily` for life and panics at the 65,537th; `GlyphInk.bounds` grows with every glyph, face and weight shaped and is never cleared.
- `BoundNum::commit_drag` and `parse_from` round to `decimals` after snapping to the step grid, so a step finer than the decimals (0.125 at 2) stores a value off the grid (0.13).
- Text editor vertical motion keeps no goal column, so moving through a short line moves the caret left for good.
- A triple-click in a multi-line `TextEdit` selects the whole buffer instead of the line.
- Dragging the only tab of a dock pane over its own pane shows a split or join wash that `move_tab` then refuses.
- A tooltip does not hide on a press on its trigger or on Escape.
- A splitter drag maps the pointer to the seam center and drops the grab offset.
- The winit runtime makes every other window follow when a frame leads by its schedule, also after a paint-only frame, so one caret blink or spinner makes every window record at refresh rate.
- `Remote` queries ask for a frame without counting it in `sent_inputs`, so a following `settle` can return on the frame before the query.
- `Remote::query` documents that a panic in the task ends only the query, but the release profile sets `panic = "abort"`.
- Every `Waker::wake` sends its own `UserEvent::Repaint` through the event-loop proxy, which has no bound.
- `Harness::window_commands` keeps every command since build with no bound, while `OffscreenHost::window_commands` holds only the last frame's.
- `PresentSchedule::suboptimal_handled` is never cleared, so a later suboptimal acquire at a size seen before does not rebuild the swapchain.
- `settle` restarts its background wait at each wake with no overall cap, and treats every timed wake as settled, the tooltip delay included.
- `PassTraffic::of` reads only the vendor id, which DX12 reports as `0x4D4F4351` for Qualcomm and GLES derives from the vendor string, so tilers read as `Drawn` there.
- `Gpu::wait_until` spins with no bound once the device wait has drained.
- `Staging::unpad_into` unmaps the buffer and leaves its `MapState` mapped.
- `SingleQuadBuffer::is_uploaded` stays true after the first upload, so the `bind_clear` assert cannot catch a missed upload.
- `CutoutPlan` packs per window into the backend-wide `CutoutTables` atlas, so two windows with different shadow sets overwrite each other's tables every frame.
- `BackdropBlur`'s expiry window counts prepares from every window, so with N windows it expires N times sooner.
- `DynamicBuffer`, the staging belt and `RenderStream::stencil` keep their high-water size for the life of the window.
- `WindowSet::follow`'s doc (`src/host/winit/window_set.rs`) links `FramePresent::followed`, which is not in scope there, so `cargo drive gate`'s doc step fails with an unresolved link.
- `cargo drive gate`'s doc lane fails on master since `c53fea50f`: `src/host/winit/window_set.rs:39` links to `FramePresent::followed`, and no item named `FramePresent` is in scope there.
